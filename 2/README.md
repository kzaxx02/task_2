# depgraph — визуализатор графа зависимостей пакетов Python

## Общее описание

CLI-инструмент для анализа и визуализации графа зависимостей пакетов
Python (формат pip). Зависимости получаются без менеджеров пакетов и
сторонних библиотек: используется только стандартная библиотека Python 3
(`urllib`, `json`, `re`).

Проект разрабатывается поэтапно. Текущее состояние: **этап 2** — сбор
данных. Для заданного пакета и версии приложение обращается к репозиторию
по URL и выводит **прямые** зависимости.

## Описание функций и настроек

### Опции командной строки

| Опция | Обязательна | Описание |
|-------|-------------|----------|
| `--package NAME` | да | Имя анализируемого пакета |
| `--repo REPO` | да | URL репозитория (http/https) или путь к файлу тестового репозитория |
| `--test-mode` | нет | Режим тестового репозитория (будет реализован на этапе 3) |
| `--version VER` | нет | Версия пакета, например `2.31.0` (по умолчанию `latest`) |
| `--ascii-tree` | нет | Вывод в формате ASCII-дерева (этап 5) |
| `--filter SUBSTR` | нет | Не учитывать пакеты с подстрокой в имени (этап 3) |

### Как извлекаются зависимости

1. По URL репозитория формируется адрес JSON-описания пакета в формате
   PyPI JSON API:
   - заданная версия: `<repo>/pypi/<package>/<version>/json`;
   - `latest`: `<repo>/pypi/<package>/json`.
2. Ответ загружается через `urllib` и разбирается как JSON.
3. Из поля `info.requires_dist` берутся строки зависимостей (PEP 508).
4. Каждая строка разбирается: выделяются имя (нормализуется по PEP 503) и
   ограничение версии. Зависимости с маркером `extra == ...` относятся к
   необязательным группам и не считаются прямыми, поэтому пропускаются.
   Дубликаты удаляются.

Для публичного PyPI используйте `--repo https://pypi.org`.

### Обработка ошибок

При ошибке выводится `Ошибка: ...` в stderr, код завершения 2:

- неверные значения параметров (проверка этапа 1);
- репозиторий недоступен или превышено время ожидания (15 с);
- пакет или версия не найдены (HTTP 404) или другая HTTP-ошибка;
- ответ не является корректным JSON или имеет неверную структуру;
- не удалось разобрать строку зависимости;
- `--test-mode` пока не поддерживается.

### Структура

```
src/depgraph/cli.py           разбор опций, main()
src/depgraph/config.py        проверка параметров, класс Config
src/depgraph/errors.py        исключения приложения
src/depgraph/fetcher.py       загрузка метаданных пакета по HTTP
src/depgraph/requirements.py  разбор строк зависимостей PEP 508
src/depgraph/output.py        форматирование вывода
tests/                        модульные тесты (unittest)
tests/fake_repo.py            локальный сервер, имитирующий PyPI JSON API
run.sh, Makefile              запуск и тесты
```

## Сборка и тесты

Сборка не требуется. Нужен Python 3.8+.

```
make test
```

или

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты не обращаются к интернету: используется локальный сервер
`tests/fake_repo.py`.

## Примеры использования

Реальный репозиторий:

```
$ ./run.sh --package requests --repo https://pypi.org --version 2.31.0
```

Ожидаемый вывод (необязательные зависимости `PySocks` и `chardet`,
помеченные `extra`, не выводятся):

```
Прямые зависимости requests 2.31.0:
  - charset-normalizer <4,>=2
  - idna <4,>=2.5
  - urllib3 <3,>=1.21.1
  - certifi >=2017.4.17
```

Примеры на локальном тестовом сервере (`<URL>` — его адрес):

```
$ ./run.sh --package demo --repo <URL> --version 1.0.0
Прямые зависимости demo 1.0.0:
  - alpha >=1.0
  - beta-pkg <2,>=1
  - gamma >=3

$ ./run.sh --package demo --repo <URL>
Прямые зависимости demo 2.0.0:
  - alpha

$ ./run.sh --package empty --repo <URL> --version 1.0
Прямые зависимости empty 1.0:
  (прямых зависимостей нет)
```

Ошибки:

```
$ ./run.sh --package demo --repo <URL> --version 9.9
Ошибка: пакет или версия не найдены в репозитории (<URL>/pypi/demo/9.9/json)
$ ./run.sh --package requests --repo http://127.0.0.1:1
Ошибка: не удалось подключиться к http://127.0.0.1:1/pypi/requests/json: <urlopen error [Errno 111] Connection refused>
$ ./run.sh --package A --repo tests/data/test_repo.txt --test-mode
Ошибка: тестовый режим будет реализован на этапе 3
```
