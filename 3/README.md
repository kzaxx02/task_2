# depgraph — визуализатор графа зависимостей пакетов Python

## Общее описание

CLI-инструмент для анализа и визуализации графа зависимостей пакетов
Python (формат pip). Зависимости получаются без менеджеров пакетов и
сторонних библиотек: используется только стандартная библиотека Python 3
(`urllib`, `json`, `re`).

Проект разрабатывается поэтапно. Текущее состояние: **этап 3** —
построение графа зависимостей с учётом транзитивности: рекурсивный DFS,
фильтрация пакетов по подстроке, обработка циклов, тестовый режим.

## Описание функций и настроек

### Опции командной строки

| Опция | Обязательна | Описание |
|-------|-------------|----------|
| `--package NAME` | да | Имя анализируемого (корневого) пакета |
| `--repo REPO` | да | URL репозитория (http/https) или путь к файлу тестового репозитория |
| `--test-mode` | нет | Брать данные из файла тестового репозитория вместо URL |
| `--version VER` | нет | Версия корневого пакета, например `2.31.0` (по умолчанию `latest`) |
| `--ascii-tree` | нет | Вывод в формате ASCII-дерева (этап 5) |
| `--filter SUBSTR` | нет | Не учитывать пакеты, в имени которых есть подстрока (с учётом регистра) |

### Построение графа

Граф строится рекурсивным обходом в глубину (`graph.py`, класс
`GraphBuilder`), начиная с `--package`:

- у каждого пакета запрашиваются прямые зависимости;
- пакет, уже включённый в граф, повторно не обходится (общие зависимости
  не дублируются);
- **фильтр**: пакеты, имя которых содержит подстроку `--filter`, не
  попадают в граф, их собственные зависимости не обходятся (если пакет не
  достижим другим путём). Если фильтру соответствует сам корневой пакет,
  выводится ошибка;
- **циклы**: пакет, который встретился в текущей цепочке рекурсии,
  повторно не обходится, а цикл записывается в отчёт (например,
  `A -> B -> C -> A`). Находятся циклы, соответствующие обратным рёбрам
  DFS, то есть каждый цикл обнаруживается хотя бы одним представителем.

### Реальный репозиторий

Данные берутся как на этапе 2 (PyPI JSON API, `--repo https://pypi.org`).
Для корневого пакета используется версия `--version`, для транзитивных
зависимостей — последняя доступная версия (ограничения версий пока не
учитываются). Необязательные зависимости (`extra`) пропускаются.

### Тестовый репозиторий (`--test-mode`)

Вместо URL в `--repo` указывается путь к текстовому файлу. Формат:

```
# строка, начинающаяся с «#», и пустые строки игнорируются
A: B C
B: C
C:
```

- одна строка на пакет: `ПАКЕТ: ЗАВИСИМОСТЬ ЗАВИСИМОСТЬ ...`;
- имена состоят только из больших латинских букв;
- пакет, упомянутый как зависимость, но не описанный в файле, считается
  не имеющим зависимостей; корневой пакет должен быть описан в файле;
- `--version` в тестовом режиме не используется.

Примеры файлов находятся в `tests/data/`: `test_repo.txt`, `chain.txt`,
`diamond.txt`, `cycle.txt`, `self_loop.txt`, `filter.txt`.

### Формат вывода

```
Граф зависимостей пакета <корень>:
(пакеты, содержащие '<подстрока>', не учитываются)   <- только с --filter
  <пакет> -> <зависимости через запятую или (нет зависимостей)>
Пакетов в графе: N
Циклических зависимостей нет.   или   список циклов
```

Пакеты перечисляются в порядке обхода DFS.

### Обработка ошибок

При ошибке выводится `Ошибка: ...` в stderr, код завершения 2:

- неверные значения параметров;
- недоступный репозиторий, пакет или версия не найдены, неверный ответ
  репозитория;
- файл тестового репозитория нельзя прочитать или он имеет неверный
  формат (сообщение содержит номер строки);
- корневой пакет не описан в тестовом файле или исключён фильтром;
- слишком глубокая цепочка зависимостей (переполнение рекурсии).

### Структура

```
src/depgraph/cli.py           разбор опций, main()
src/depgraph/config.py        проверка параметров, класс Config
src/depgraph/errors.py        исключения приложения
src/depgraph/fetcher.py       загрузка метаданных пакета по HTTP
src/depgraph/requirements.py  разбор строк зависимостей PEP 508
src/depgraph/sources.py       источники данных: репозиторий и тестовый файл
src/depgraph/testrepo.py      чтение файла тестового репозитория
src/depgraph/graph.py         построение графа (DFS), фильтр, циклы
src/depgraph/output.py        форматирование вывода
tests/                        модульные тесты (unittest)
tests/fake_repo.py            локальный сервер, имитирующий PyPI JSON API
tests/data/                   файлы тестовых репозиториев
run.sh, Makefile              запуск и тесты
```

## Сборка и тесты

Сборка не требуется. Нужен Python 3.8+.

```
make test
```

или

```
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тесты не обращаются к интернету.

## Примеры использования

Реальный репозиторий:

```
$ ./run.sh --package requests --repo https://pypi.org --version 2.31.0
```

### Тестовый репозиторий: различные случаи

Простой граф (`test_repo.txt`):

```
$ ./run.sh --package A --repo tests/data/test_repo.txt --test-mode
Граф зависимостей пакета A:
  A -> B, C
  B -> C
  C -> (нет зависимостей)
Пакетов в графе: 3
Циклических зависимостей нет.
```

Ромб — общая зависимость обходится один раз (`diamond.txt`):

```
$ ./run.sh --package A --repo tests/data/diamond.txt --test-mode
Граф зависимостей пакета A:
  A -> B, C
  B -> D
  D -> (нет зависимостей)
  C -> D
Пакетов в графе: 4
Циклических зависимостей нет.
```

Цикл A → B → C → A (`cycle.txt`):

```
$ ./run.sh --package A --repo tests/data/cycle.txt --test-mode
Граф зависимостей пакета A:
  A -> B
  B -> C
  C -> A, D
  D -> (нет зависимостей)
Пакетов в графе: 4
Обнаружены циклические зависимости:
  A -> B -> C -> A
```

Тот же граф с другим корнем (`--package B`):

```
$ ./run.sh --package B --repo tests/data/cycle.txt --test-mode
Граф зависимостей пакета B:
  B -> C
  C -> A, D
  A -> B
  D -> (нет зависимостей)
Пакетов в графе: 4
Обнаружены циклические зависимости:
  B -> C -> A -> B
```

Пакет, зависящий от самого себя (`self_loop.txt`):

```
$ ./run.sh --package A --repo tests/data/self_loop.txt --test-mode
Граф зависимостей пакета A:
  A -> A, B
  B -> (нет зависимостей)
Пакетов в графе: 2
Обнаружены циклические зависимости:
  A -> A
```

Фильтр (`filter.txt`). Без фильтра в графе есть пакет `AB`:

```
$ ./run.sh --package A --repo tests/data/filter.txt --test-mode
Граф зависимостей пакета A:
  A -> AB, C
  AB -> D
  D -> (нет зависимостей)
  C -> D, E
  E -> A
Пакетов в графе: 5
Обнаружены циклические зависимости:
  A -> C -> E -> A
```

С `--filter B` пакет `AB` исключается:

```
$ ./run.sh --package A --repo tests/data/filter.txt --test-mode --filter B
Граф зависимостей пакета A:
(пакеты, содержащие 'B', не учитываются)
  A -> C
  C -> D, E
  D -> (нет зависимостей)
  E -> A
Пакетов в графе: 4
Обнаружены циклические зависимости:
  A -> C -> E -> A
```

### Ошибки

```
$ ./run.sh --package Z --repo tests/data/chain.txt --test-mode
Ошибка: пакет 'Z' не описан в тестовом файле
$ ./run.sh --package AB --repo tests/data/filter.txt --test-mode --filter B
Ошибка: пакет 'AB' исключён фильтром 'B'
$ ./run.sh --package A --repo bad.txt --test-mode
Ошибка: строка 1: недопустимое имя 'b'
```
